# Текущая архитектура

Этот документ описывает текущую принятую архитектуру и инструменты проекта. Причины выбора и история пересмотра хранятся в [ADR](adr/README.md). Назначение документа определено в [ADR-0006](adr/0006-document-current-architecture.md).

## Назначение и состояние проекта

Развитие ориентировано на [цель и философию Celestial](project-goal.md), согласно [ADR-0033](adr/0033-goal-guided-development.md). Целевые возможности и реализованное устройство описываются отдельно.

Celestial3 — система разработки сайтов на WordPress, развивающаяся постепенно. Работают FSE-тема с дизайн-токенами и правилами оформления, плагин с Landing Pages, сборкой ресурсов редактора и примером статического блока; настроено Docker-окружение через wp-env. Полный процесс получения готового клиентского сайта, библиотека паттернов и иконок и комплексная SEO-проверка ещё не реализованы.

Тема отвечает за оформление, плагин — за возможности, сохраняемые при смене темы. Плагин также может содержать блоки и интерфейс. wp-env подключает локальные каталоги в `wp-content/themes/theme` и `wp-content/plugins/plugin`; отображаемое название обоих компонентов — Celestial.

wp-env устанавливается глобально; проверенная версия — 11.17.0. В корне `wordpress/` нет `package.json`, lock-файла, `.nvmrc` и локальных npm-зависимостей. Инструменты Node.js/npm находятся в `wordpress/plugin/` и описаны в [README плагина](../wordpress/plugin/README.md). Сборка темы не предусмотрена согласно ADR-0013. Параметры WordPress/PHP используют значения по умолчанию wp-env; конкретные версии ядра и PHP пока не закреплены. Инструкции запуска находятся в [README проекта](../wordpress/README.md).

Тема содержит базовые шаблоны index, home, page, single, single-landing-page, archive, search и 404. Все используют общие header/footer и соответствующую content-часть. Списки используют наследуемый Query, отрывки и пагинацию; page/single выводят заголовок и содержимое. Header подключает выбранный pattern celestial/header-title-navigation с Site Title и Navigation (стандартное меню/fallback WordPress). Footer подключает celestial/footer-copyright с редактируемым текстом «© Celestial 2026». Это минимальный каркас без проектного наполнения, реализованный в рамках ADR-0036–0039.

## Граница передачи клиенту

Согласно [ADR-0014](adr/0014-plugin-scoped-development-tools.md), вся разработка ведётся в `wordpress/`. В корне находятся тема, плагин, `.wp-env.json`, `.gitignore` и README. Окружение запускается прямой командой глобального `wp-env` из этого каталога. Конфигурации и зависимости плагина находятся внутри `plugin/`. Для клиентской поставки требуется заново собрать и включить `plugin/build/`; `node_modules/` для работы WordPress не нужен.

ADR, описание архитектуры, правила агента и приватные заметки остаются вне `wordpress/`. Клиент получает самостоятельный проект без этих материалов и истории внутреннего репозитория. Инструкции разработки и установки находятся в [wordpress/README.md](../wordpress/README.md).

При переносе конфигурации wp-env создал новое окружение; прежнее остановлено, его данные сохранены отдельно. Ядро WordPress, база данных и медиафайлы не входят в исходники и требуют отдельной миграции. Публикация и передача ещё не выполнялись.

Внутренняя библиотека хранится вне клиентского проекта. В wordpress/ переносится только выбранный код, который является источником истины; отдельного Project Composition нет. Правила — [ADR-0039](adr/0039-project-source-of-truth.md).

## Как поддерживать документ

- Обновлять затронутые разделы при принятии или замене ADR и при изменении состояния реализации.
- Показывать актуальные принятые решения со ссылками на действующие ADR. Предложения и историю замен хранить в ADR и их реестре.
- Явно различать выбранное, реализованное и ещё не определённое.
- После появления конфигураций зависимостей ссылаться на них как на источник версий и настроек, не поддерживая здесь отдельные списки версий.
- При расхождении с действующим ADR исправлять описание архитектуры; изменение решения проводить по правилам [ADR-0005](adr/0005-review-existing-decisions-before-replacement.md).
- После добавления ADR или изменения его статуса сохранять связанные изменения локальным Git-коммитом согласно [ADR-0016](adr/0016-commit-adr-changes.md).

## Черновая продуктовая страница

Добавлены шесть универсальных секционных patterns в библиотеку и тему. Шаблон front-page через content-front-page выводит обычное редактируемое содержимое страницы, без второго H1. Начальный набор блоков и инструкция находятся в теме docs/celestial-page.*. Страница и настройка главной в локальной базе не заменяют файловую архитектуру и требуют миграции при передаче. Это черновое публичное предложение продукта: без раскрытия приватного процесса, вымышленных доказательств и действующей формы заявки. Универсальность секций и разделение с продуктовым контентом закреплены в ADR-0040; композиция использует ADR-0034, 0036–0039.

Общая композиционная Group шаблонов имеет blockGap 0 по ADR-0041. Секции главной страницы также объединены отдельной Group с нулевым gap внутри Post Content; внутренние расстояния секций не обнулены.

## Иконки Lucide

По ADR-0042–0043 коллекция Lucide встроена в includes/icons Celestial и подключается явно. Используется core/icon и публичный API WordPress 7.1+; без собственного блока, JS и генератора. Готовый набор lucide-static 1.55.0 (2141 SVG) и лицензия сохранены в Git и входят в поставку. При отсутствии API регистрация пропускается с уведомлением администратору. Общие ограничения дизайна редактора сохранены.

При создании оформления агент выбирает иконки только из установленной коллекции Lucide, по смыслу блока и с проверкой фактического SVG. Каталог поиска — assets/manifest.php; его подписи являются краткими названиями. Это правило ADR-0044 не меняет служебные иконки WordPress и не отключает стандартную коллекцию.

Добавлена универсальная секция information-six-items: Subtitle, H2, два ряда по три пункта с Lucide, H3 и текстом. Выбран стиль Paragraph subtitle/plain; CSS подключён по ADR-0028. Паттерн доступен в Features, существующая главная автоматически не изменяется.

По ADR-0045 работа над элементами сначала выполняется и проверяется внутри wordpress/. В library/ результат переносится только по явному запросу владельца; автоматического пополнения или обратной синхронизации нет. Существующие библиотечные версии могут отличаться от текущего проекта.

Текущий Subtitle в wordpress/ доработан: текст muted, перед ним декоративная точка primary через CSS ::before. По явному запросу владельца текущая реализация сохранена в library/blocks/paragraph/subtitle/dot; plain остаётся альтернативой. Сайт не зависит от библиотеки.

По ADR-0046 Subtitle и заголовок секции образуют отдельную Group с меньшим внутренним gap. В проектном information-six-items: spacing 20 внутри, spacing 50 до колонок. Изменена только текущая проектная реализация и её экземпляр на главной; библиотека и остальные patterns сохранены.

Обслуживание по ADR-0047 включает проверку существующих элементов проекта и library/ по актуальным правилам, включая правила, принятые после их создания. Это выявление расхождений, без автоматической синхронизации библиотеки. Аудит этим решением не запускался.

По ADR-0050 core/icon оформляется темой: plain 2rem/contrast; circle и rounded-square — рисунок 2rem/base в контейнере 4.5rem/primary. Размеры и локальный радиус 0.5rem заданы custom-токенами, геометрия в assets/blocks/icon.css, варианты зарегистрированы в functions.php. Library не обновлялась.

По явному запросу владельца оформление Icon сохранено в library/blocks/icon: базовый контракт Plain, самостоятельные variations Circle и Rounded square с реализациями default. Базовые токены и CSS вынесены в base.json/base.css; SVG не дублируются. Текущий проект не изменён.

По ADR-0051 новые и явно дорабатываемые секции с вводным блоком имеют две вложенные смысловые Group: Subtitle + заголовок и основное содержимое. Внутренний gap вводного блока меньше межгруппового gap, который не превышает вертикальный padding секции. Правило принято; существующие реализации этим шагом не переработаны.

ADR-0051 применён к проектному information-six-items и его экземпляру на главной: два ряда колонок теперь внутри отдельной Group контента. Внутренний gap вводной группы 20, межгрупповой 50, padding секции 70. Библиотечная версия этим изменением не обновлялась.

После визуальной оценки межгрупповой gap information-six-items увеличен до spacing 60 (32px при корневом шрифте 16px). Остальные внутренние интервалы сохранены; библиотека не обновлялась.

По запросу владельца текущий information-six-items сохранён в library/sections/information-six-items с группировкой и gap 20/60/50, padding 70. Иконка Надёжность на главной возвращена к Plain.

В проектном Subtitle применяется CSS text-transform: uppercase независимо от регистра введённого текста. Библиотечный dot этим шагом не обновлён по ADR-0045.

По ADR-0052 перед изменением существующих файлов или удалением в library/ агент показывает точный список и ожидает подтверждения владельца. Прямой общий запрос не заменяет согласования списка. Изменения рабочего wordpress/ не распространяются на библиотеку.


Экспериментальная contentOnly-блокировка information-six-items пока остаётся в коде и экземпляре главной, но её эффективность не подтверждена владельцем. ADR-0053 удалён по явному запросу владельца; дальнейшее поведение требует уточнения.

По ADR-0054 принят целевой клиентский режим редактирования содержимого с сохранением структуры блоков и секций; владелец сохраняет возможность сборки. Механизмы блокировки и разделение доступа требуют реализации и проверок. Новый ADR сам по себе не меняет текущий редактор; эксперимент contentOnly не считается подтверждением полной защиты.

По ADR-0055 изменена глобальная шкала H1–H6: 48/36/24/20/18/16px при корневом шрифте 16px, значения хранятся в rem. Базовый текст и sm не изменены; fluid-размеры не добавлены. Library не обновлялась.

Владелец визуально подтвердил шкалу ADR-0055 как более различимую; она принята для дальнейшей работы.

После ревизии из wordpress/theme/patterns удалены первоначальные Hero, Benefits, Features, Process, FAQ и Contact, ранее удалённые из библиотеки. В теме остались header-title-navigation, footer-copyright и information-six-items. Вставленные блоки главной сохранены в базе и не зависят от удалённых файлов patterns.

В Header убраны фиксированные якорные Navigation Link. Navigation без ref и вложенных ссылок использует штатный fallback WordPress; библиотека не изменена.

## Первый тест системы: мебель на заказ

Создан локальный сайт вымышленной компании «Форма»: семь выбранных секций, локальные фотографии Unsplash, собственная страница и Navigation-меню в базе. Прежняя страница Celestial сохранена. Палитра адаптирована к интерьерному оформлению, роли токенов сохранены. Проектная документация — wordpress/theme/docs/furniture-demo.md. Демонстрационная форма не отправляет данные; сайт не опубликован внешне и исключён из индексации локальной настройкой. Library не менялась.

По ADR-0056 структура нового сайта выбирается из контекста бизнеса. Основной формат — многостраничный; без подробностей агент выбирает консервативный состав страниц, учитывая явные требования владельца. Текущий мебельный тест остаётся одностраничным до отдельного поручения на переработку.

## Оглавление одиночной записи (2026-10-15)

Реализован динамический `celestial/table-of-contents` в blocks/table-of-contents плагина, с явным PHP-модулем includes/table-of-contents. Собирает H2/H3 текущей записи и добавляет отсутствующие anchors только при рендере основного содержимого; ссылки работают без JS, а view.js подсвечивает текущий раздел при прокрутке. Готовый build создан существующим pipeline. В content-single слева TOC, справа Post Content; стили блока — в theme.json и CSS темы, глобальные controls остаются скрыты. Библиотека не изменена. Обход синхронизированных паттернов и динамических заголовков не реализован; подробные ограничения и проверки описаны в wordpress/theme/docs/blocks/table-of-contents.md.

Оглавление content-single закреплено в левой колонке через sticky на ширине от 783px, с ограниченной высотой и учётом admin bar. На узком экране находится над статьёй. Типографика соответствует основному тексту; активная ссылка получает aria-current="location" и выделяется средствами темы.

## Рабочая галерея секций (2026-10-15)

Главная локального проекта временно заменена подборкой 30 пронумерованных секций для визуального отбора владельцем. Кандидаты находятся в patterns темы, каталог номеров и HTML-снимок — в wordpress/theme/docs/section-gallery*. Исходная главная и меню сохранены в docs/backups/2026-10-15-before-section-gallery внутри темы. ## Дизайнерская роль и проверка композиций

Приняты ADR-0057–0058: агент самостоятельно предлагает визуальное направление, выбирает выразительные приёмы по задаче, опирается на просмотренные существующие примеры и дорабатывает результат после реальной визуальной проверки. Это требования к дальнейшей работе, а не отчёт о внедрении фонового видео, узоров или шкалы теней. Код сайта и library этим принятием не меняются; старые варианты не считаются повторно проверенными. Q-0004, Q-0005 и Q-0008 остаются открытыми.
