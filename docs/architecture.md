# Текущая архитектура

## Система и граница поставки

Celestial — внутренний процесс разработки сайтов на WordPress/Gutenberg с собственной FSE-темой. [Цель](project-goal.md) описывает ожидаемый результат; [навигация](README.md) ведёт к практическим руководствам. Обоснования — в ADR, текущий порядок работы — [здесь](development-workflow.md).

Клиентский проект находится в wordpress/. theme/ отвечает за представление, plugin/ — за сохраняемую при смене темы функциональность. Тема без сборки; глобальный wp-env запускается из wordpress/, .wp-env.json подключает оба компонента и активирует тему. Инструменты Node.js и сборка плагина находятся в plugin/. Конфигурации — источник версий. [Разработка и запуск](../wordpress/README.md), [стандарты](../wordpress/docs/coding-standards.md). Основания: ADR-0004, 0008–0009, 0013–0014, 0029–0032.

Внутренние docs/, ADR, AGENTS.md и library/ не входят в поставку. references/ — игнорируемые локальные материалы, доступ только по конкретному поручению. Для передачи отдельно нужны база, загруженные медиа и результаты сборки плагина. [Проверки и границы](maintenance.md). Основания: ADR-0014–0015, 0039, 0047, 0052.

## Тема

Готовые theme.json, templates, parts и CSS используются напрямую. Палитра содержит 10 ролей с base как фоном и contrast как текстом; spacing 10–90, локальные Ubuntu/Roboto и шкала заголовков сохранены. Точные настройки — [руководства темы](../wordpress/theme/README.md) и theme.json. Основания: ADR-0017, 0019, 0022, 0055.

Templates содержат только Group/Template Part с общей Group default/gap0. Содержательные блоки — в parts; header/footer сейчас содержат прямую разметку Core. Контент главной находится в базе; файловые theme patterns удалены после тестовой подборки. Главная — одностраничный демо-лендинг шкафов-купе «Форма», предыдущие материалы сохраняются отдельно. [Шаблоны](../wordpress/theme/docs/templates.md), [состав лендинга и ограничения проверок](../wordpress/theme/docs/wardrobe-landing.md). Основания: ADR-0036, 0040–0041.

Зарегистрированы Paragraph Subtitle и Caption, Icon Plain/Circle/Rounded square. FAQ главной использует Core Accordion; дополнительные CSS привязаны к блокам через wp_enqueue_block_style. Core patterns отключены, пользовательские этим не удаляются. Иерархия групп/интервалов документирована в [композиции секций](../wordpress/theme/docs/sections.md). Основания: ADR-0027–0028, 0046, 0050–0051, 0059–0060.

## Плагин

celestial.php явно подключает PHP-модули landing-pages, editor-policy, icons, table-of-contents, inquiries и page-metadata. Собственные блоки example-static и table-of-contents собираются в build/blocks; общий editor/index.js остаётся минимальным входом. [Структура и сборка](../wordpress/plugin/README.md). Основания: ADR-0030–0032.

Lucide встроен готовыми ресурсами с лицензией; core/icon использует lucide/<name>, без отдельного плагина и генератора. Регистрация требует API WordPress 7.1+, при отсутствии пропускается с уведомлением. [Модуль](../wordpress/plugin/includes/icons/README.md). Основания: ADR-0042–0044.

Оглавление в single находится слева от Post Content, имеет sticky и подсветку текущего раздела; на обычную страницу автоматически не добавляется. Inquiries сохраняет тестовые обращения локально, без внешней доставки; page-metadata выводит description из явного excerpt. Эти возможности существуют в коде, но не являются полной системой выпуска сайта. [Оглавление](../wordpress/theme/docs/blocks/table-of-contents.md), [форма и метаданные](../wordpress/theme/docs/wardrobe-landing.md).

## Редактор и незавершённое

Controls дизайна скрыты глобально, токены и их CSS сохраняются. Полноценное разделение клиентского редактирования содержимого и сборки владельцем ещё не реализовано: contentOnly сам по себе не гарантирует защиту структуры/порядка секций. [Состояние и сценарии проверки](../wordpress/theme/docs/editor-controls.md). Основания: ADR-0034, 0054.

Общие модели Shapes/теней, дальнейшее уточнение ширины содержимого, возвращение padding/gap и автономная работа остаются [открытыми вопросами](questions/README.md). Готовность всех элементов библиотеки по новым правилам не проверена; этот перенос документации не является аудитом сайта, WordPress-базы или библиотеки. Автоматический выпуск и комплексная SEO-проверка пока не реализованы.

## Внутренние рабочие материалы

Библиотека хранит варианты блоков и секции; проект не зависит от неё в runtime. Разработка сначала в wordpress/, сохранение в library по поручению, изменения существующих файлов — по точному подтверждению. [Порядок](library-workflow.md). Основания: ADR-0037–0040, 0045, 0047, 0052.

Отзывы владельца находятся в [design-reviews](design-reviews/README.md), отложенные темы — в questions. При проектировании учитываются контекст, реальные примеры и фактический рендер, без навязывания одной композиции всем сайтам. [Проектирование](design-workflow.md). Основания: ADR-0026, 0033, 0056–0058, 0061.

Тематическая документация — рабочая точка входа; ADR сохраняют историю и остаются основанием выбора. При изменении решения обновлять затронутые руководства, этот обзор при изменении состояния и навигацию в одной задаче. Основания: ADR-0006, 0062.
