## Статусы

| Статус | Значение |
| --- | --- |
| Открыт | Идея сохранена, к обсуждению ещё не приступили. |
| В обсуждении | Тему обсуждаем или исследуем; решение ещё не принято. |
| Закрыт | Вопрос разрешён или рассмотрение завершено; причина и результат записаны. Может ссылаться на принятый ADR. |
| Отменён | Тема больше не актуальна или владелец отказался от неё; причина записана. |
| Реализован | Связанная работа выполнена и проверена; есть ссылка на ADR, коммит или другой результат. |

Принятый ADR сам по себе не означает выполненную реализацию. Если решение принято, но код ещё не готов, вопрос можно закрыть с пояснением «решение принято, реализация ожидается».

## Порядок работы

1. Когда владелец говорит «обсудим позже», создать карточку по [шаблону](template.md) со следующим постоянным номером `Q-NNNN` и добавить её в реестр. Перед этим проверить, нет ли уже такой темы.
2. Записать идею, контекст и вопросы для обсуждения, не выдавая предположения за решения. Фраза «обсудим позже» означает сохранение темы, а не запуск работы над ней.
3. Возвращаться к теме по запросу владельца. Перед предложениями проверять действующие ADR; карточка не заменяет их требования.
4. Обновлять карточку и реестр вместе. При закрытии, отмене или реализации указать дату и результат; связать с ADR и подтверждением реализации, если они есть.
5. Сохранять историю существенных изменений. По просьбе пересмотреть тему открыть ту же карточку заново с записью причины; не удалять старый результат и не переиспользовать номера.

Карточки и реестр находятся во внутренней документации и не входят в передачу клиенту. Приватные исходники из `references/` сюда не копируются. Добавление и изменение вопроса не требует отдельного ADR; ADR нужен для значимого архитектурного решения по результатам обсуждения.
