# Работа с внутренней библиотекой

Библиотека library/ — приватные поддерживаемые реализации; references/ — отдельные локальные исходные наработки. Ни одна не передаётся клиенту. Код wordpress/ — фактический выбранный результат, не создаём Project Composition или второй реестр выбора.

## Выбор

В library/blocks/<block>/<style-variation>/<variant>/ находятся альтернативы оформления; library/sections/<section>/ содержит композиции patterns. Subtitle — style variation core/paragraph, dot/line — альтернативные реализации, не дополнительные обязательные стили проекта. Выбирать одну реализацию на проект со стабильным slug и классом (subtitle / is-style-subtitle). Не добавлять лишний уровень default; базовое оформление определяется theme.json.

Контракт variation описывает README; реализация — description.md, style.json и при необходимости style.css/ресурсы. Шаблоны карточек находятся в library/templates/. Фиксировать назначение, зависимости, адаптацию, несовместимости, ограничения и выполненные проверки. Статусы: Черновик, Проверен, Устарел. Превью не обязательно. Обычное пополнение не требует нового ADR.

При выборе переносить в wordpress/ только необходимую реализацию, patterns и их зависимости. Адаптировать к токенам проекта и проверить редактор/frontend. Не оставлять runtime-imports или символические ссылки на library/references. Обновление библиотечного исходника не перезаписывает адаптированный код проекта автоматически. Документация поставки описывает установленный результат, альтернативы остаются здесь.

## Разработка и сохранение

Сначала реализовать и проверить улучшение внутри wordpress/. По умолчанию library не менять. Сохранить результат в библиотеку только по явному поручению владельца, обобщив названия, тексты и подсказки, категории по назначению. Не переносить тексты продукта, фиксированные якоря, перекрёстные ссылки или ID конкретного сайта. Технический celestial/ не является продуктовой привязкой.

Перед изменением существующих файлов показать точный список и суть изменений и дождаться подтверждения. Перед удалением, даже по прямому запросу, показать все удаляемые файлы/каталоги и последствия и дождаться подтверждения. Перезапись, переименование и перемещение также считаются изменением; удаление старого пути указывать явно. Общий запрос «обнови» или «перенеси» не подтверждает точный список существующих файлов.

Создание новых записей разрешено явным поручением; затрагивание существующих файлов требует подтверждения списка. Повторно не согласовывать уже подтверждённые операции; расширение согласовать отдельно. Запросы на изменение wordpress/ не распространяются на library/. Read-only проверка и предложение не требуют согласования.

Обслуживание проверяет старые элементы по актуальным правилам, но не разрешает автоматическое исправление — см. [проверки и передача](maintenance.md). Само создание этой документации библиотеку не изменяет.

Основания: ADR-0037–0040, 0045, 0047, 0052. История — в [реестре](adr/README.md).
