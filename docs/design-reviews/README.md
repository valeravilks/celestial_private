# Отзывы владельца о дизайне

Внутренние заметки о конкретных просмотренных результатах. Они помогают учитывать вкус и комментарии владельца в следующих итерациях и проектах. Не входят в wordpress/ и клиентскую поставку.

## Когда записывать

После содержательной оценки владельцем страницы, секции или визуального приёма сохранять её в текущей задаче, не ожидая отдельного «запомни». Фиксировать одобрение, замечания, отказ и границы оценки. Короткое общее одобрение можно добавить в существующую заметку; не создавать файл на каждую реплику. Не приписывать владельцу причины, которых он не называл: интерпретацию агента помечать отдельно.

Один файл на страницу или итерацию: YYYY-MM-DD-short-subject.md по [шаблону](template.md). Продолжение той же оценки добавлять датированным разделом; при существенно новой версии создавать новую запись со ссылкой на прежнюю. Пересмотр явно отмечать, сохраняя историю. Не считать старое одобрение оценкой нового рендера. При наличии подходящего снимка сохранять его рядом; иначе указывать исходный снимок кода/коммит и ограничения восстановления (включая базу WordPress). Не ссылаться на временные файлы как постоянный источник.

## Как учитывать

Перед дизайном страницы, подбором или доработкой секций просматривать относящиеся к задаче отзывы. Поиск по назначению и приёмам: hero, фото, подписи, фон, FAQ, CTA. Выбирать подходящие предпочтения под контекст бизнеса; в пояснении результата кратко отмечать, какие комментарии учтены. Не навязывать одобренный приём каждому сайту.

Текущий явный запрос владельца имеет приоритет над прежними предпочтениями; действующие ADR проверяются отдельно. При противоречии ADR соблюдать порядок согласования, а не заменять правило заметкой. Если оценки расходятся, учитывать контекст и последнее явное уточнение; при существенной неоднозначности уточнить.

Это не список автоматически разрешённых изменений. Отложенные темы вести в docs/questions; значимые общие правила — в ADR. Ссылаться на них из отзыва вместо дублирования решений. Похвала не разрешает изменение или перенос library; соблюдать отдельное подтверждение. В ходе обычного пополнения отзывов новые ADR не нужны.
