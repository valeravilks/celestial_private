# Проверки, обслуживание и передача

## Соответствие решениям

По поручению «займись обслуживанием проекта» проверять текущую реализацию и все существующие элементы library/ по актуальным применимым ADR, цели и правилам работы. Для такого аудита читать полные записи и статусы, а не только руководства. Дата создания элемента и прошлый успешный просмотр не доказывают соответствие новым решениям.

Для расхождения указать путь/элемент, действующее требование и ADR, фактическое поведение, влияние и предлагаемое действие. Различать ошибку, историческую реализацию в ожидании адаптации, ещё не реализованный выбор и допустимое отличие проекта от библиотеки. Не подгонять решения под код молча.

Обслуживание не разрешает заменять ADR, переносить проектные изменения в библиотеку или массово исправлять её. Выполнять только согласованный объём; library — по [точному подтверждению](library-workflow.md). references не читать без отдельного разрешения. Этот документ не запускает аудит, фоновую работу или автоматизацию.

## Готовность сайта

Проверки выбирать по изменению: PHP/сборка, регистрация блоков, сохранённый контент, редактор, frontend, интерактивные сценарии, адаптивность, доступность и контраст. Для готового сайта проверить также структуру заголовков, метаданные, ссылки, индексируемость, sitemap и применимые robots/canonical. Наличие намерения в ADR не является реализацией комплексной SEO-проверки. Автоматический выпуск полностью готовых клиентских сайтов ещё не реализован.

Сохранять результат и ограничения проверки. Визуальную оценку выполнять по [порядку проектирования](design-workflow.md), файловые templates проверять рекурсивно по [руководству](../wordpress/theme/docs/templates.md). Учитывать пользовательские версии в базе отдельно.

## Локальные приватные материалы

references/ исключена из Git, общего поиска, архивов, клиентской передачи, публикаций и загрузок. Читать/искать только по явному запросу владельца для конкретной задачи. Не применять git add -f. Разрешение использовать отдельное решение не разрешает перенос всего исходника или приватных данных; копирование в отслеживаемые файлы — только в порученном объёме.

## Передача

Передавать отдельную копию проекта из wordpress/, без внутреннего репозитория, его истории, docs/, library/ и references/. Документация внутри wordpress/ самостоятельна, без ссылок за его пределы. Базу и загруженные медиа мигрировать отдельно; HTML-снимок не является резервной копией всей базы.

Проверить скрытые файлы, секреты, приватные данные, символические ссылки и зависимости от внешних файлов. Не включать автоматически локальные резервные копии/демо-материалы в публикацию; оценить их содержимое. Для плагина собрать и включить build/, без node_modules. Тема поставляется напрямую без сборки. Публичная передача/публикация выполняется в порученном объёме, этот документ её не запускает.

Основания: ADR-0014–0015, 0033, 0039, 0047, 0052, 0058; [реестр](adr/README.md).
