# ADR-0038: Альтернативные реализации одной style variation

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

## Контекст

Владелец хочет иметь несколько библиотечных реализаций Subtitle, но использовать одну на конкретном сайте. Термин для Subtitle — style variation блока Paragraph.

## Решение

Использовать структуру library/blocks/<block>/<style-variation>/<variant>/. Например paragraph/subtitle/dot и paragraph/subtitle/line. Paragraph соответствует core/paragraph; subtitle — зарегистрированный стиль; dot/line — альтернативные библиотечные реализации этого стиля, а не дополнительные обязательные стили проекта.

Для конкретного проекта выбирать одну реализацию каждой style variation. Сохранять стабильный slug, например subtitle, и класс is-style-subtitle независимо от выбранного варианта. Паттерны используют это имя. При несовместимости конкретной секции с некоторыми реализациями явно описывать зависимость.

Каталог style variation содержит README с общим контрактом; вариант — description.md, style.json и при необходимости готовый style.css. Дополнительные ресурсы добавлять по необходимости. Не создавать лишний уровень default: базовое оформление блока задаёт theme.json, пока не определена самостоятельная потребность в альтернативных базовых стилях.

## Альтернативы

Регистрировать все dot/line/pill на каждом сайте как независимые стили. Это допускает смешивание вариантов и передаёт клиенту невыбранные альтернативы.

## Последствия

- Паттерны не зависят от названия библиотечного варианта.
- Контракт стиля нужно сохранять при адаптации.
- Реальная регистрация стиля появляется только при реализации и переносе выбранного варианта.
