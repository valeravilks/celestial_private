# ADR-0028: Дополнительный CSS отдельных блоков темы

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

## Контекст

Владелец поручил перенести механизм подключения CSS для Core-блоков из старой темы, чтобы дополнять JSON-оформление сложными CSS-правилами. Сейчас нужен механизм и пустой пример для Button, без переноса старого оформления.

## Решение

В functions.php на хуке init подключать файлы через wp_enqueue_block_style. Список имён без core/ хранить в $styled_blocks; каждому имени соответствует assets/blocks/<name>.css и handle celestial-<name>. Передавать src и path через функции доступа к файлам темы.

Начать с button и пустого assets/blocks/button.css. Group из старого списка не подключать без соответствующего файла и принятого оформления. Готовый CSS использовать непосредственно, без сборки.

Базовые свойства и токены сохранять в theme.json и JSON style variations. Отдельный CSS применять для сложных состояний, селекторов и responsive-поведения, ограничивая его нужным блоком или классом варианта. Подключение CSS само по себе не регистрирует style variation; новые варианты этим решением не вводятся.

Инструкции расширения хранить в wordpress/theme/docs/block-styles.md.

## Альтернативы

Собирать всё дополнительное оформление в одном глобальном CSS или больших строках JSON. Перенесённый механизм позволяет разделить код по блокам и использовать штатную загрузку WordPress.

## Последствия

- У темы есть расширяемый способ подключения готового CSS без сборки.
- Каждая запись списка требует существующего файла.
- WordPress управляет способом загрузки и возможным встраиванием CSS в зависимости от контекста.
- Пустой пример не меняет оформление кнопки.
