# ADR-0016: Git-коммиты после добавления ADR

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

## Контекст

Репозиторий инициализирован, но до этого решения коммитов не было. Архитектурные записи и реализация должны сохраняться в истории, чтобы можно было восстановить состояние проекта и проследить изменения.

## Решение

После добавления ADR или изменения его статуса агент выполняет необходимые проверки и создаёт локальный Git-коммит с ADR, обновлениями реестра, архитектуры и связанной реализацией задачи. Отдельное подтверждение обычного локального коммита не требуется: владелец разрешил этот порядок.

Независимые решения оформлять отдельными ADR. Несколько связанных ADR одной завершённой задачи допустимо сохранять одним коммитом. В сообщении коммита указывать затронутые ADR или понятную суть изменения.

Перед коммитом проверять статус Git и состав индекса. Добавлять файлы задачи явно; не включать чужие или несвязанные изменения и игнорируемые приватные материалы. Если задача требует согласования замены ADR, сначала получить его по ADR-0005. Если коммит не удаётся, сообщить причину, сохранив выполненную работу.

Создать начальный коммит текущей системы, включая ранее принятые ADR. Коммиты выполняются локально; публикация и push этим решением не разрешаются.

## Альтернативы

Оставлять изменения без коммитов до отдельного запроса. В таком случае история ADR и реализация не имеют сохранённых контрольных точек.

## Последствия

- Завершённые задачи с ADR получают контрольную точку в истории Git.
- Проверка состава коммита становится частью работы агента.
- Приватные наработки остаются вне Git согласно ADR-0015.
