# ADR-0009: Разделение проекта на тему и плагин

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

## Контекст

Проект использует WordPress, Gutenberg и FSE-тему. Необходимо разделить оформление сайта и функциональность, которая должна сохраняться при смене темы.

## Решение

Разрабатывать два отдельных компонента WordPress:

- `wordpress/theme/` — собственная блочная FSE-тема: шаблоны, части шаблонов, стили, `theme.json` и паттерны оформления.
- `wordpress/plugin/` — обычный валидный WordPress-плагин: типы записей, данные, интеграции, бизнес-логика и возможности, которые должны сохраняться при смене темы.

Плагин может содержать собственные блоки и интерфейс. Критерий размещения функциональности — необходимость её сохранения при смене темы, а не только наличие визуального представления.

На текущем этапе создать только пустые каталоги. Исходники, файлы регистрации темы и плагина, сборка и подключение к окружению будут добавлены отдельно. Пустые каталоги пока не являются распознаваемыми WordPress темой и плагином.

## Альтернативы

Размещать всю функциональность в теме. Это связывает возможности сайта с оформлением и затрудняет смену темы.

## Последствия

- Оформление и сохраняемая функциональность разрабатываются отдельно.
- При наполнении каталогов необходимо создать корректные самостоятельные тему и плагин.
- Выбор локального окружения не определяет границы ответственности компонентов.
- Git не хранит пустые каталоги; до добавления файлов они существуют только в текущем рабочем каталоге.
