# ADR-0030: PHP-модули функциональности в includes

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

## Контекст

Владелец выбрал структуру старого плагина для постепенного переноса. PHP-функциональность сайта должна быть отделена от темы, расширений редактора и исходников блоков.

## Решение

Хранить каждый PHP-модуль в wordpress/plugin/includes/<feature>/index.php. Подключать модули явными require_once из celestial.php. Модуль регистрирует свои функции через хуки WordPress; все глобальные функции используют celestial_. Классы не вводить только ради группировки хуков.

Первым модулем перенести landing-pages: публичный CPT landing-page, show_in_rest: true, поддержка title/editor/thumbnail, без архива, со slug landing-page. Это пример организации функциональности. Старое исключение Landing Pages из sitemap, общий модуль sitemap и Dashboard сейчас не переносить: они требуют самостоятельного выбора поведения.

Не использовать автоматическое подключение всех файлов: состав активных модулей должен быть явным. Инструкции расширения хранить в README плагина.

## Альтернативы

Собирать весь PHP-код в celestial.php или автоматически загружать каталоги. Выбранная структура сохраняет небольшой входной файл и явные границы модулей.

## Последствия

- PHP-функциональность расширяется отдельными каталогами.
- Landing Pages становятся доступны в WordPress и Gutenberg.
- Смена состава модулей выполняется явно в точке входа.
