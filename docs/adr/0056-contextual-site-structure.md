# ADR-0056: Выбор структуры сайта по контексту бизнеса

- **Статус:** Принято
- **Дата:** 2026-10-14
- **Автор решения:** Владелец проекта

## Контекст

Первый тест — запрос сайта компании по производству корпусной мебели — был реализован как одна страница. Владелец ожидал многостраничный сайт с отдельными направлениями, информацией о компании и контактами. Система должна самостоятельно выводить разумную структуру из контекста, не сводя любой запрос к лендингу.

## Решение

При запросе «создай сайт» выбирать структуру по типу бизнеса, предложениям, аудитории и задачам посетителя. Основной рабочий формат системы — многостраничный сайт. При отсутствии подробностей использовать консервативный, понятный состав страниц, характерный для данного бизнеса, без искусственного расширения числа страниц.

Явные требования владельца имеют приоритет: список страниц, формат лендинга, ограничения объёма и другие детали определяют результат. Одностраничный сайт не считать автоматическим default; выбирать его при явном запросе либо обоснованной узкой задаче, например отдельном рекламном предложении.

Когда подробностей мало, агент самостоятельно предлагает и реализует первую рабочую структуру, кратко обозначая предположения. Если вопросы запрещены, не останавливать работу ради обычного выбора страниц. Не выдумывать факты о бизнесе для наполнения: создавать явно обозначенный демонстрационный контент при необходимости.

Для компании с несколькими направлениями рассматривать главную, обзор направлений/услуг, отдельные страницы существенных направлений, о компании и контакты. Портфолио, FAQ, блог и другие разделы добавлять при понятной пользе, а не ради полноты. Для мебельного бизнеса кухни и шкафы/гардеробные являются разумными кандидатами отдельных страниц, а не обязательной универсальной схемой.

Обычные страницы сайта создавать как WordPress Pages. Использовать существующий landing-page для отдельных лендингов, когда это соответствует задаче; не превращать все страницы компании и услуг в этот CPT. Конкретный состав страниц фиксировать в материалах проекта и реализации, без отдельного ADR на каждую страницу.

Сейчас зафиксировать принцип. Текущий мебельный тест не перерабатывать: владелец сначала хочет пройти остальные выводы и решения.

## Альтернативы

Автоматически создавать одну страницу — не соответствует основному формату владельца. Всегда требовать полный список страниц — мешает получению первого результата по краткому запросу. Всегда создавать одинаковый большой набор — не учитывает бизнес и добавляет лишнее.

## Последствия

Первая версия лучше отражает тип сайта, ожидаемый владельцем. Агент отвечает за разумную информационную структуру и объяснение предположений. Многостраничность не заменяет качество содержания и проверку маршрутов, меню и шаблонов.
