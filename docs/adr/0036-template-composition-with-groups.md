# ADR-0036: Композиция шаблонов через Group и template parts

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

## Контекст

ADR-0035 разрешил только ссылки на template parts. Владелец уточнил, что шаблонам также нужны контейнеры для компоновки частей, чтобы собирать общую структуру страницы.

## Решение

В wordpress/theme/templates/*.html разрешить только core/group и core/template-part. Group может задавать layout и вложенную композицию; его дочерние блоки также должны быть только Group или template-part. Разрешена HTML-разметка оболочки, соответствующая Group, а также пробелы и переносы строк. Свободную HTML-разметку вне оболочек блоков не добавлять.

Header, footer и содержимое страниц размещать в parts/*.html. Query, Post Content, Heading, другие содержательные блоки и прямые ссылки на паттерны в templates не размещать. Части могут содержать нужную разметку, блоки, другие части и паттерны без циклических ссылок.

При проверке исходников рекурсивно проверять все уровни вложенности шаблона, разрешённые типы блоков, существование частей по slug и соответствие HTML оболочке Group. Правило не требует наличия Group в каждом шаблоне: шаблон из одних ссылок на части тоже допустим.

В index.html добавить Group-обёртку для main-index, сохранив содержимое части. Будущую композицию header/footer/content и других шаблонов определять постепенно.

## Альтернативы

Оставить только template-part согласно ADR-0035. Это требует переносить любую композиционную обёртку в часть. Разрешить любые блоки в шаблоне — размывает границу между композицией страницы и её содержимым.

## Последствия

- Шаблоны управляют композицией через Group, содержимое остаётся в parts.
- Проверять нужно вложенные блоки, а не только верхний уровень.
- Пользовательские шаблоны в базе данных могут перекрывать исходники; их политика остаётся отдельным вопросом.
