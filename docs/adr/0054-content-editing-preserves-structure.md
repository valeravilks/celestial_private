# ADR-0054: Редактирование содержимого с сохранением структуры

- **Статус:** Принято
- **Дата:** 2026-10-14
- **Автор решения:** Владелец проекта

## Контекст

Скрытые controls оформления не запрещают добавление Paragraph по Enter или перестановку блоков. Владелец хочет, чтобы клиент менял содержание готового сайта, сохраняя согласованную композицию. Прежний ADR-0053 об отдельном атрибуте удалён по запросу владельца; цель следует закрепить отдельно от конкретной реализации.

## Решение

Принять принцип клиентского режима: разрешать редактирование предусмотренного содержимого (тексты, ссылки, изображения и другие явно предусмотренные поля), сохраняя структуру и оформление готовой страницы. Добавление, удаление и перестановка внутренних блоков секций, а также перестановка секций готовой страницы не входят в клиентское редактирование содержимого.

Для владельца сохранять отдельный сценарий сборки и изменения композиции из готовых паттернов. Принцип не отменяет самостоятельную сборку страниц владельцем и не требует запретить её всем ролям одинаково. Конкретное разделение доступа и режимов предстоит определить при реализации.

Использовать стандартные механизмы WordPress, рассматривая templateLock contentOnly как механизм блокировки внутренней структуры контейнера. Не полагаться на автоматическое применение этого режима ко всем вставкам patterns. Не считать блокировку секции запретом перемещения самой секции на странице: уровень композиции страницы проверяется отдельно.

Не добавлять contentOnly механически повсюду и не объявлять задачу выполненной по наличию атрибута. При реализации проверять фактические сценарии: Enter и вставка текста, добавление и удаление блоков, перестановка блоков и секций, изменение предусмотренных полей, доступные режимы изменения структуры и редактор кода. Учитывать уже вставленные экземпляры и сохранённые версии в базе.

На этом шаге закрепить только принцип, без новых изменений кода, прав доступа, patterns или library. Текущий эксперимент contentOnly остаётся неподтверждённой реализацией, а не гарантией защиты структуры.

## Альтернативы

Только скрывать controls дизайна — сохраняет возможность изменения структуры. Использовать один атрибут без проверок — не подтверждает весь клиентский workflow. Запретить сборку всем пользователям — мешает цели самостоятельной работы владельца.

## Последствия

Готовность клиентского режима требует проверки поведения редактора и уровня страницы. Потребуется явно определить доступ владельца и клиента. Сохранённый контент и автоматические ограничения WordPress не считаются достаточным подтверждением сами по себе.
