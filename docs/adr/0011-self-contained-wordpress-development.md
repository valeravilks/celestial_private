# ADR-0011: Самостоятельный проект разработки в wordpress

- **Статус:** Заменено [ADR-0012](0012-global-wp-env.md)
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

Заменено 2026-10-13: wp-env устанавливается глобально. ADR-0012 сохраняет размещение разработки в `wordpress/` и границу приватной документации. Исходное решение ниже сохранено для истории.

## Контекст

ADR-0010 неверно отделил инструменты локальной разработки от передаваемого проекта. Владелец уточнил, что вся разработка сайта ведётся внутри `wordpress/`, включая wp-env, npm и локальные зависимости. Приватными остаются документы внутреннего процесса Celestial.

## Решение

Использовать `wordpress/` как самостоятельный корень разработки и передачи проекта. Хранить внутри него:

- `theme/` и `plugin/` с исходниками компонентов.
- `.wp-env.json` с путями `./theme` и `./plugin`.
- `package.json`, `package-lock.json` и `.nvmrc`.
- Локально установленный `node_modules/` и необходимые будущие инструменты сборки.
- Самостоятельную документацию установки и разработки.

Все команды npm и wp-env выполнять из `wordpress/`. Зависимости устанавливать по lock-файлу; `node_modules/` хранить локально и исключать из Git. Это не исключает локальные зависимости из каталога разработки.

ADR, описание архитектуры, правила агента и приватные заметки хранить за пределами `wordpress/`. Передавать клиенту самостоятельный проект без приватных документов и истории внутреннего репозитория. Установленные npm-зависимости можно восстановить через `npm ci`; передача их готовой копии не обязательна.

Перед передачей проверять файлы, включая скрытые файлы и символические ссылки, на секреты, приватные материалы и зависимости от внутреннего хранилища. Ядро WordPress, база данных и медиафайлы по-прежнему требуют отдельного переноса при миграции сайта.

## Альтернативы

Сохранить окружение в корне внутреннего репозитория согласно ADR-0010. Это делает передаваемый проект зависимым от внешних инструментов и не соответствует уточнённому требованию владельца.

## Последствия

- Проект можно разрабатывать и запускать из одного каталога независимо от приватной документации.
- Перенос `.wp-env.json` меняет идентификатор окружения wp-env: прежнее окружение и его данные сохраняются отдельно, а по новому пути создаётся новое.
- Корень репозитория содержит внутренние документы; корень WordPress-проекта содержит код и инструменты разработки.
