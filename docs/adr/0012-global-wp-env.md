# ADR-0012: Глобальная установка wp-env

- **Статус:** Заменено [ADR-0014](0014-plugin-scoped-development-tools.md)
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

Заменено 2026-10-13: из корня `wordpress/` удалены npm-конфигурация и `.nvmrc`; их будущее размещение относится к плагину. ADR-0014 сохраняет глобальный wp-env и границу передачи. Исходный текст ниже сохранён для истории.

## Контекст

ADR-0011 предусматривает локальные зависимости в самостоятельном WordPress-проекте. wp-env был установлен как dev-зависимость каждого проекта. Владелец предпочитает общий инструмент локальной разработки, установленный глобально.

Документация wp-env описывает как глобальную, так и локальную установку; быстрый старт использует глобальную. Глобальная установка соответствует выбранному процессу работы с несколькими проектами.

## Решение

Устанавливать `@wordpress/env` глобально в выбранном окружении Node.js и запускать `wp-env` из каталога `wordpress/`. Не включать его в зависимости проекта. При использовании nvm глобальные пакеты относятся к выбранной версии Node.js.

Сохранить `.wp-env.json`, `.nvmrc`, `package.json`, `package-lock.json`, исходники темы и плагина и инструкции в `wordpress/`. npm-скрипты могут вызывать глобальный wp-env. Автоматическую активацию темы после запуска выполнять прямой командой `wp-env run cli wp theme activate theme`.

Локальный `node_modules/` остаётся местом будущих зависимостей проекта, исключённым из Git. Для запуска текущего каркаса установка npm-зависимостей проекта больше не требуется. Если появятся инструменты сборки компонентов, их зависимости будут определяться отдельно.

Сохранить границу передачи из ADR-0011: разработка и передаваемые исходники находятся в `wordpress/`; ADR, правила агента и приватные заметки — вне него. Глобальный инструмент является предварительным требованием окружения получателя и описывается в самостоятельном README. Передача проекта не включает приватные материалы и историю внутреннего репозитория; база данных и медиафайлы требуют отдельной миграции.

## Альтернативы

Локальная установка wp-env фиксирует версию отдельно для каждого проекта, но повторяет установку и набор зависимостей. Этот вариант заменён по прямому указанию владельца.

## Последствия

- Один глобальный инструмент может обслуживать несколько проектов в одном окружении Node.js.
- Версия wp-env не фиксируется lock-файлом проекта; обновление глобального инструмента может затронуть несколько проектов.
- При смене версии Node.js через nvm нужно проверить наличие глобального wp-env.
- Конфигурация и данные текущего окружения сохраняются: путь `.wp-env.json` не меняется.
