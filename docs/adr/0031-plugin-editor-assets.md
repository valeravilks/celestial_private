# ADR-0031: Отдельный код расширений редактора

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

## Контекст

Владелец хочет сохранить отдельную область для общих изменений Gutenberg. В старом проекте editor/index.js является пустой точкой расширения с готовой сборкой и подключением.

## Решение

Использовать wordpress/plugin/editor/index.js как вход для общих расширений редактора. Собирать его через локальный @wordpress/scripts в build/editor. Подключать index.js на enqueue_block_editor_assets, используя dependencies и version из сгенерированного index.asset.php.

На текущем этапе entry point содержит только комментарий: новых изменений поведения редактора нет. Если JS или asset-файл отсутствуют, подключение пропускать без фатальной ошибки. Для проверки ресурсов сначала выполнять сборку.

Инструменты и их lock-файл хранить внутри плагина согласно ADR-0014: @wordpress/scripts 32.0.0 и npm-run-all 4.1.5, Node.js 24 через .nvmrc и engines, engine-strict через .npmrc. Команды build/start параллельно запускают отдельные процессы editor и blocks; start означает наблюдение за исходниками, а не запуск WordPress. wp-env остаётся глобальным.

build/ и node_modules/ не включать в Git. build/ заново создавать по lock-файлу; при передаче готового плагина на сервер включать результаты сборки. Сборка относится только к плагину, тема остаётся без сборки.

## Альтернативы

Смешивать общие изменения редактора с кодом отдельного блока или хранить инструменты в корне wordpress/. Это размывает границы, выбранные владельцем.

## Последствия

- Общие расширения редактора имеют отдельный вход и bundle.
- Отсутствие сборки не ломает PHP, но JS-возможности не подключаются.
- Установка по npm ci и сборка обязательны для воспроизводимой поставки ресурсов.
