# ADR-0062: Тематическая документация как рабочая точка входа

- **Статус:** Принято
- **Дата:** 2026-10-15
- **Автор решения:** Владелец проекта

## Контекст

Повторение решений в AGENTS.md, обзоре архитектуры и ADR увеличивает обязательное чтение. Владелец выбрал практическую документацию по темам вместо единой сводки всех правил. Изменение порядка чтения ADR-0005 объяснено в обсуждении и явно разрешено поручением реализации.

## Решение

Поддерживать актуальные тематические руководства на основе действующих решений. Использовать существующие документы: локальный wp-env — в wordpress/README.md, сборка — в README плагина, токены и оформление — в руководствах темы. Недостающие темы дополнить, например соглашения PHP, композицию секций, проектирование, библиотечный workflow и обслуживание. Не создавать обязательный к чтению общий summary/current-rules.

AGENTS.md содержит короткие обязательные ограничения и маршрут чтения docs/README.md. Перед задачей читать цель и необходимые тематические руководства; весь архив ADR не загружать автоматически. Полные ADR и статусы читать при неоднозначности, исключениях, возможном конфликте, изменении архитектурного выбора, проверке соответствия или полноты руководства. При новом/изменяемом решении проверить реестр и относящиеся записи, чтобы не опереться на устаревший документ.

Руководства описывают действующий порядок и установленное поведение; принятые, но не реализованные возможности отмечаются отдельно. Архитектурный обзор сохраняется по ADR-0006, но описывает текущие компоненты и связи вместо хроники правок. Подробное правило имеет основное место и ссылки из соседних документов. Версии и настройки подтверждаются конфигурациями.

Сохраняется защита от молчаливой замены решений: до противоречащей реализации сообщить владельцу номер/название ADR, действующее требование, суть замены, последствия и по возможности совместимую альтернативу. Дождаться явного подтверждения конкретной замены; общий запрос на функциональность им не является, ранее полученное конкретное подтверждение не спрашивается повторно. До подтверждения допустимы предложение и независимая совместимая работа. После подтверждения — новый ADR, взаимные ссылки и статус заменённого, без удаления исходного контекста и решения. Совместимые изменения не требуют дополнительного согласования.

ADR остаются единственным журналом архитектурных решений, источником обоснований и истории. Заменённые записи не устанавливают текущие требования. При расхождении с действующим ADR исправлять руководство; при расхождении кода не подгонять решение молча. Реестр сохраняет все статусы. При принятии/замене ADR обновлять затронутую документацию в той же задаче и коммите; реализация ограничена порученным объёмом, незавершённое обозначается явно.

Самостоятельная документация установленного проекта находится в wordpress/, без ссылок на приватный процесс. Внутренние рабочие руководства, отзывы и история остаются вне него. Library и references не изменяются этим переносом документации.

## Альтернативы

Общий summary — сохраняет ещё один слой пересказа и не заменяет практических инструкций. Постоянное чтение полного архива — не нужно для обычной задачи. Удаление истории — теряет причины и основания выбора.

## Последствия

Обязательное чтение AGENTS.md сокращается; дополнительная документация выбирается по задаче. Это не обещание точного размера контекста: прочитанное ранее в текущем разговоре не исчезает. Требуются согласованное обновление руководств и адресное чтение первоисточников. Проверка противоречий, Git-коммиты и точное подтверждение библиотечных изменений сохраняются.
