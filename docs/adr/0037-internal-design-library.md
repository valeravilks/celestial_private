# ADR-0037: Внутренняя библиотека Blocks и Sections

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

## Контекст

Владельцу нужна постепенно пополняемая библиотека вариантов оформления и секций, из которой агент выбирает подходящие элементы. Передаваемый клиенту WordPress-проект не должен раскрывать все альтернативы внутренней системы.

## Решение

Создать library/ в корне внутреннего репозитория, вне wordpress/. Хранить её в приватной истории Git. blocks/ содержит варианты оформления блоков, sections/ — композиции patterns. Это поддерживаемая библиотека; references/ остаётся отдельным игнорируемым локальным хранилищем исходных наработок.

В library/templates/ хранить шаблоны описания style variation, её реализации и секции. Карточки описывают назначение, зависимости, адаптацию, ограничения и выполненные проверки. Статусы реализаций: Черновик, Проверен, Устарел. Статические превью не обязательны.

Сейчас создать структуру и шаблоны, не наполняя их реальными стилями или секциями. Subtitle использовать как пример контракта. Пополнение в рамках принятых правил не требует отдельного ADR; пересмотр принципов требует решения.

## Альтернативы

Хранить все альтернативы внутри темы проекта. Это передаёт клиенту внутреннюю библиотеку и смешивает возможности системы с выбранным результатом.

## Последствия

- Агент получает явный каталог для поиска и выбора элементов.
- Библиотека не входит в клиентскую поставку и не является runtime-зависимостью сайта.
- Код, описания и проверки элементов требуют согласованного поддержания.
