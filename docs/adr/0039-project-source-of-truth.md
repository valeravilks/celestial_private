# ADR-0039: Код проекта как источник истины о выбранных элементах

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

## Контекст

Владелец уточнил: выбранное оформление уже находится в проекте. Отдельный Project Composition или список выбранных вариантов дублировал бы этот результат.

## Решение

Считать фактический код wordpress/ источником истины о составе и реализации сайта. Не вводить отдельный реестр выбранных вариантов или Project Composition.

При выборе из library/ переносить только необходимую реализацию, выбранные patterns, зависимости и ресурсы. Адаптировать к токенам и требованиям проекта, сохраняя стабильные slugs. Сайт должен работать без доступа к library/ и references/: без runtime-imports или символических ссылок на них.

Документация внутри wordpress/ описывает только фактически установленное поведение и использование. Библиотечные альтернативы и правила их выбора остаются вне клиентского проекта. Обновление библиотечного исходника не перезаписывает адаптированный код проекта; перенос улучшений выполняется явно с проверками.

Проверять редактор, frontend и применимые сценарии после переноса. Исключать внутреннюю библиотеку, приватные документы и Git-историю из клиентской поставки. Дополнительные вопросы о проектных переопределениях документации остаются в Q-0003.

## Альтернативы

Поддерживать отдельный список выбора или подключать библиотеку напрямую. Первый создаёт второй источник состояния, второй делает клиентский проект зависимым от приватной системы.

## Последствия

- Состав проекта виден в его исходниках.
- Клиент получает самостоятельный выбранный результат.
- Адаптированные реализации могут отличаться от библиотеки; обновления требуют осознанной работы.
