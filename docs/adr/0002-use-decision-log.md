# ADR-0002: Использование Decision Log

- **Статус:** Заменено [ADR-0003](0003-use-adrs-as-single-decision-record.md)
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

Решение заменено 2026-10-13. Исходный контекст и решение ниже сохранены для истории; отдельный Decision Log удалён.

## Контекст

Проект развивается постепенно через [ADR-0001](0001-incremental-development-through-adrs.md). Помимо подробных архитектурных записей нужен общий журнал, позволяющий быстро увидеть, какие значимые решения приняты и почему. В него могут входить решения о продукте, процессе разработки и организации работы.

## Решение

Вести Decision Log в файле `docs/decision-log.md`. Каждая запись содержит постоянный идентификатор, дату, статус, автора решения, краткое описание выбора, его причину и ссылки на подробности, если они есть.

Для архитектурных решений создавать ADR и добавлять в журнал краткую запись со ссылкой на него. Полный контекст, альтернативы и последствия хранить в ADR; журнал служит общей точкой входа. Для остальных значимых решений достаточно записи в журнале, пока не требуется отдельное описание.

При пересмотре решения добавлять новую запись со ссылкой на предыдущую. Предыдущую помечать как заменённую и связывать с новой, сохраняя исходный текст. Статус архитектурного решения в журнале должен соответствовать его ADR.

## Альтернативы

Продолжать вести только реестр ADR. Такой подход сохраняет архитектурную историю, но не даёт общего места для значимых решений других типов. Decision Log дополняет существующий реестр.

## Последствия

- Значимые решения проекта доступны в одном журнале.
- Краткие записи позволяют понять выбор и перейти к подробному ADR.
- При добавлении и пересмотре архитектурного решения необходимо согласованно обновлять ADR, его реестр и журнал.
- Повседневные действия, задачи и мелкие исправления не требуют записи в журнале.
