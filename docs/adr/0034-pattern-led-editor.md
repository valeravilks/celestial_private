# ADR-0034: Сборка страниц из паттернов без ручной настройки дизайна

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

## Контекст

Владелец хочет, чтобы редактор собирал страницы из готовых паттернов и менял содержимое, сохраняя согласованное оформление. Прежние решения разрешали выбор цветов и отдельных параметров расстояний и типографики. Теперь на текущем этапе нужны общие максимальные ограничения дизайна, включая padding и gap.

## Решение

Принять общий принцип: оформление задаётся исходниками темы и готовыми композициями; пользователю не предлагается вручную настраивать дизайн стандартными controls. Редактирование текста, изображений, ссылок и вставка блоков/паттернов остаются доступными. Это не блокировка содержимого или прав доступа.

В theme.json глобально отключить controls цветов текста/фона/ссылок, градиентов и duotone, padding/margin/blockGap, типографических деталей, границ, теней, размеров и редактирования layout; appearanceTools оставить false. blockGap: false скрывает control, сохраняя возможность генерации заданного дизайном CSS. Не добавлять overrides отдельных блоков; удалить ранее созданные typography-overrides Heading/Paragraph.

Сохранить палитру, spacing-пресеты, семейства/файлы шрифтов, размеры и custom-токены в theme.json: они нужны готовым стилям и паттернам. Для скрытия выбора размеров и семейств без удаления их CSS использовать один глобальный block_editor_settings_all фильтр в модуле плагина includes/editor-policy. Он очищает editor-only списки размеров/семейств и legacy-настройки дизайна. Поле __experimentalFeatures зависит от версии WordPress и требует проверки при обновлениях.

Сохранить типографику Heading и Paragraph: общие элементы H1–H6 и глобальные стили базового текста. Скрытие controls не меняет их оформление. Проверять соответствие при обновлении WordPress.

Padding и gap пока также отключены. Возможное возвращение ограниченного выбора только этих параметров остаётся открытым вопросом Q-0002. Синхронизация паттернов, блокировка структуры, доступ к Site Editor и сторонние controls не реализуются этим решением.

## Альтернативы

Разрешать выбор только из токенов, как раньше. Владелец считает, что даже допустимые значения могут нарушить композицию. Отключать отдельно каждый блок — повторяет правила и расходится с требованием общей политики.

## Последствия

- Пользователь работает с готовыми композициями, а изменения дизайна выполняются в коде или готовых стилях.
- Библиотека паттернов ещё развивается; эти ограничения сами по себе не создают готовые композиции.
- Это ограничение стандартного UI, а не гарантия невозможности изменения дизайна: сохранённые атрибуты, ручной код, inline-форматирование и нестандартные controls могут требовать дополнительной политики.
- Ранее принятые токены, layout, подключение CSS блоков и разделение темы/плагина сохраняются.
