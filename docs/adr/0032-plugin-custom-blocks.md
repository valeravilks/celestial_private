# ADR-0032: Исходники и регистрация собственных блоков

- **Статус:** Принято
- **Дата:** 2026-10-13
- **Автор решения:** Владелец проекта

## Контекст

Владелец хочет перенести структуру разработки блоков и пока только статический пример. В старом build/ есть результаты, не обеспеченные исходниками; копировать их нельзя.

## Решение

Хранить блоки в wordpress/plugin/blocks/<block>/ с block.json и исходниками JS/SCSS. Через @wordpress/scripts собирать в build/blocks с флагом --blocks-manifest. На init регистрировать коллекцию по blocks-manifest.php через wp_register_block_types_from_metadata_collection; сохранить fallback старого исходника для отсутствующих API коллекций. Если манифест отсутствует, регистрацию пропускать.

Перенести только example-static с именем cel/example-static, text domain celestial и apiVersion 3. index.js регистрирует edit и save; edit.js задаёт отображение в редакторе, save.js — сохраняемую разметку. editor.scss действует в редакторе, style.scss — в обоих контекстах. Цвета и расстояния примера адаптировать к токенам принятой темы вместо старых произвольных значений.

Другие блоки и старые результаты build/ не переносить. Интерактивные и динамические примеры остаются последующими задачами. Для статического примера experimental-modules не нужен и не включается.

Сборка и поставка результатов следуют ADR-0031. После добавления или изменения блока выполнять build и проверять регистрацию и рендер. Общую политику namespace всех будущих блоков можно уточнить отдельно; сейчас сохраняется имя выбранного примера.

## Альтернативы

Регистрировать каждый блок вручную или переносить старые bundles. Коллекция использует штатный механизм WordPress; новая сборка подтверждает соответствие результата исходникам.

## Последствия

- Добавление block.json в исходники и повторная сборка обновляют коллекцию.
- Без build блоки не зарегистрированы, хотя сам плагин может работать.
- Изменения save-разметки уже используемого статического блока требуют проверки совместимости сохранённого контента.
