## Как добавлять решения

Самостоятельно выделять независимые решения в отдельные ADR, независимо от количества сообщений пользователя. Связанные детали одного решения описывать вместе. Критерий разделения — возможность пересмотреть решение независимо от остальных. Основание — [ADR-0007](0007-split-independent-decisions.md).

Перед новыми изменениями проверять относящиеся к задаче действующие ADR. При противоречии сначала сообщить владельцу проекта, какие решения затронуты, что предлагается изменить и каковы последствия. Заменять решения и реализовывать противоречащие изменения только после явного подтверждения их замены. Подробности — в [ADR-0005](0005-review-existing-decisions-before-replacement.md).

1. Скопировать [шаблон](template.md) в файл `NNNN-short-title.md` со следующим последовательным номером.
2. Описать задачу, рассматриваемые варианты, решение и его последствия. Для обсуждаемого решения использовать статус «Предложено».
3. После принятия решения владельцем проекта установить статус «Принято», указать дату и добавить запись в реестр.
4. При пересмотре принятого решения создать новый ADR со ссылкой на предыдущий. В предыдущем установить статус «Заменено ADR-NNNN» и добавить ссылку на новую запись, сохранив исходный контекст и решение.
5. Обновить затронутые разделы [описания текущей архитектуры](../architecture.md), если решение меняет описанную систему или инструменты.
6. После необходимых проверок сохранить ADR и связанные изменения задачи локальным Git-коммитом согласно [ADR-0016](0016-commit-adr-changes.md).

Статусы: «Предложено», «Принято», «Отклонено», «Заменено ADR-NNNN».

ADR нужны для решений, которые влияют на устройство системы, ограничения или дальнейшее развитие. Обычные исправления и детали реализации не требуют отдельного ADR.
