# ADR-0047: Проверка актуальных правил при обслуживании

- **Статус:** Принято
- **Дата:** 2026-10-14
- **Автор решения:** Владелец проекта

## Контекст

Библиотечный элемент может быть создан до принятия нового правила. Поэтому корректная на момент создания реализация позднее может расходиться с действующими ADR. Владелец хочет учитывать такие расхождения при обслуживании проекта, в том числе при отдельно порученной автономной работе.

## Решение

При поручении «займись обслуживанием проекта» проверять текущую реализацию и все существующие элементы library/ на соответствие применимым действующим ADR, правилам агента и цели проекта. Дата создания элемента не освобождает его от оценки по актуальным правилам. Заменённые ADR учитывать как историю, не как действующие требования.

Для каждого расхождения указывать элемент, затронутое правило, наблюдаемое поведение, влияние и предлагаемое действие. Различать нарушение текущего требования, историческую реализацию, ожидающую адаптации, и допустимую разницу выбранного проекта с библиотекой. Не выдавать прежнюю проверку элемента за подтверждение его актуального соответствия новым правилам.

Обслуживание включает такую проверку, но не разрешает автоматически менять принятые ADR, переносить проектные правки в library/ или обновлять все библиотечные версии. Соблюдать ADR-0045: перенос и изменение библиотечных реализаций требуют явного поручения. Если обслуживание отдельно разрешает исправления в конкретном объёме, выполнять их в этом объёме; иначе представлять обнаруженные расхождения и предложения. Не читать references/ без отдельного разрешения.

Текущий пример: библиотечный information-six-items предшествует правилу ADR-0046, а проектный экземпляр уже адаптирован. При будущем обслуживании оценить эту разницу, а не предполагать автоматическую синхронизацию.

Сейчас зафиксировать правило без запуска аудита, фоновых задач или исправлений существующих элементов.

## Альтернативы

Проверять только новые изменения — оставляет накопленные расхождения незамеченными. Автоматически синхронизировать всю библиотеку — нарушает явный workflow сохранения результатов.

## Последствия

Обслуживание даёт картину соответствия актуальной архитектуре и очередь осознанных исправлений. Само наличие старых элементов не означает, что новые правила отменены или уже применены ко всей библиотеке.
