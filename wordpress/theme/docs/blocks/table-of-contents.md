# Table of Contents

Динамический блок `celestial/table-of-contents` находится в плагине: `blocks/table-of-contents/` (метаданные, редактор, PHP-рендер). Модуль `includes/table-of-contents/index.php` извлекает заголовки и добавляет недостающие якоря при выводе. Плагин нужно собирать через `npm run build`; готовый build обязателен при поставке. Frontend-скрипт view.js подсвечивает текущий раздел при прокрутке; без JavaScript обычные ссылки оглавления продолжают работать.

## Когда использовать

Table of Contents — рекомендуемый приём навигации для длинных статей и содержательных страниц с несколькими разделами: руководств, подробных описаний услуг и ответов на сложные вопросы. Он помогает увидеть структуру материала, перейти к нужному разделу и понимать своё положение при чтении. Для коротких страниц и небольших рекламных секций добавлять оглавление автоматически не нужно.

## Как использовать в записи или странице

В редакторе вставить блок **Table of Contents** из категории Widgets. Добавить в содержимое стандартные Heading H2 и, при необходимости, H3: список формируется автоматически, вручную дублировать названия и ссылки не нужно. Уровни выбирать по смысловой структуре документа.

Блок можно вставлять прямо в содержимое обычной страницы WordPress (Page), а не только записи (Post). В этом случае он собирает заголовки этой страницы и включает их якоря при выводе. После вставки проверить ссылки на опубликованной странице; отдельный полный сценарий Page пока не проверен.

В текущем шаблоне одиночной записи блок уже находится слева от Post Content: второй экземпляр в текст вставлять не нужно. На обычные страницы эта компоновка автоматически не распространяется. Для аналогичного размещения слева можно собрать Columns внутри содержимого страницы: оглавление в левой Column, текст и заголовки — в правой. Для закрепления использовать у левой Column класс `celestial-article-toc`; это работа владельца/разработчика над композицией, без включения клиентских controls дизайна.

Если оглавление вынесено из Post Content в другую часть шаблона страницы, потребуется отдельно подключить обнаружение этой части в модуле якорей. Сами templates сохраняют композицию Group/template-part, а содержательные блоки размещаются в parts.

## Поведение

Оглавление текущей записи выводит непустые core/heading H2 и H3, включая вложенные в обычные контейнеры. H1 и H4–H6 не включаются. H3 выделены отступом. Нет заголовков — нет навигации. Заголовок навигации — «На этой странице», доступное имя nav — «Оглавление». Контекст postId/postType задаёт запись. Защищённый паролем текст не раскрывается.

Заданные автором anchors сохраняются. Для остальных формируются уникальные ID с post ID и порядковым номером, с учётом занятых anchors; одинаковые тексты не создают одинаковых ID. Изменение порядка меняет автоматически рассчитанные ссылки: это ссылки внутри текущей страницы, не постоянные внешние адреса. База данных не изменяется. Повторяющиеся ручные anchors автор должен исправлять самостоятельно.

Добавление якорей ограничено основным содержимым одиночной записи или страницы с TOC в самом содержимом, шаблоне single или части content-single. Для других пользовательских частей/шаблонов нужно отдельно расширить проверку. Синхронизированные паттерны, динамически сгенерированные заголовки, произвольный HTML и заголовки сторонних блоков не обходятся. В редакторе отображается список доступного содержимого записи; переходы проверяются на frontend.

## Оформление

`theme.json` → `styles.blocks["celestial/table-of-contents"]`: typography (размер, интерлиньяж), color.text, elements.link.color.text и spacing.blockGap. Дополнительные детали списка, отступ H3 и focus outline — в `assets/blocks/table-of-contents.css`, подключённом через wp_enqueue_block_style. Это оформление темы, не зависимости плагина. Глобальные controls дизайна не включены.

Компоновка слева/справа находится в `parts/content-single.html`; блок не создаёт собственных колонок и может быть размещён отдельно.

## Проверки первой версии

Сборка плагина, динамическая регистрация, 10 ссылок на 10 реальных заголовков, переход в браузере, вложенные и повторяющиеся заголовки, резервирование ручного anchor и пустое содержимое проверены. На фактической ширине 582px колонки складываются без горизонтального переполнения. Полный сценарий редактирования в Site Editor и точная ширина 390px ещё не проверены.

## Закрепление и текущий раздел

В левой колонке content-single используется класс celestial-article-toc. При ширине от 783px оглавление sticky с отступом под панель администратора и ограничением высоты по viewport; длинное оглавление прокручивается внутри себя. Ниже этого порога оно остаётся в потоке над текстом. Оформление в theme.json соответствует основному тексту: Ubuntu/md/regular/normal, contrast.

view.js выбирает последний заголовок выше линии чтения у верхнего края, а в конце страницы — последний пункт. Ссылка получает aria-current="location"; CSS темы выделяет её primary, полужирным и подчёркиванием. Прокрутка обрабатывается через requestAnimationFrame, без сторонних библиотек. Якорные переходы учитывают верхний отступ панели администратора. Анимация прокрутки не добавлена.

Проверка закрепления: в браузере при прокрутке sidebar остаётся на 48px под admin bar; шрифт оглавления и текста — 16px. Проверены смена aria-current при прокрутке, совпадение выбранного пункта после якорного перехода и последний пункт в конце страницы.
