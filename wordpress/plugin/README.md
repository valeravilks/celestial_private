# Celestial — плагин

## Структура

- celestial.php — точка входа и явное подключение PHP-модулей.
- includes/<feature>/index.php — функциональность сайта. Сейчас подключён landing-pages: публичный тип записи Landing Page, доступный в Gutenberg.
- editor/index.js — вход для общих расширений Gutenberg; пока содержит только комментарий.
- blocks/<block>/ — исходники собственных блоков; сейчас только example-static.
- build/editor/ и build/blocks/ — генерируемые результаты; node_modules/ — локальные зависимости. Эти каталоги исключены из Git.

## Команды

Из каталога плагина:

```sh
nvm install
nvm use
npm ci
npm run build
```

`npm run start` наблюдает за исходниками editor и blocks. Отдельные процессы доступны через build:editor, build:block, start:editor и start:block. WordPress запускается глобальной командой `wp-env start` из родительского каталога проекта.

## Добавление PHP-функциональности

Создать includes/<feature>/index.php, защитить прямой доступ проверкой ABSPATH, использовать функции с префиксом celestial_ и хуки WordPress. Затем добавить явный require_once в celestial.php. Код отображения темы остаётся в теме.

Пример Landing Pages не вводит отдельную политику sitemap и не меняет Dashboard. После изменения rewrite-правил типов записей обновить постоянные ссылки WordPress; локально можно выполнить `wp-env run cli wp rewrite flush` из родительского каталога проекта.

## Общие расширения редактора

Добавлять код и imports в editor/index.js, затем выполнить сборку. PHP подключает build/editor/index.js только в редакторе, а зависимости и версия берутся из index.asset.php. При отсутствии файлов подключение пропускается.

## Собственные блоки

Каждый блок располагается в отдельном каталоге blocks/ с block.json. Пример cel/example-static:

- index.js — регистрация JS-блока и общих стилей.
- edit.js — интерфейс редактора.
- save.js — сохраняемая разметка.
- editor.scss — стили редактора.
- style.scss — стили редактора и сайта.

Сборка создаёт block metadata и blocks-manifest.php. PHP регистрирует блоки из манифеста на init. После изменения исходников повторить build и проверить блок в WordPress. Для static-блоков изменение save может требовать миграции ранее сохранённого содержимого.

## Передача и установка

Перед поставкой выполнить npm ci и npm run build. В устанавливаемый плагин включать build/, даже несмотря на его исключение из Git. Без результатов сборки PHP-модули работают, но блоки и общий JS редактора не загружаются. node_modules/ на сервере для работы плагина не требуется.
