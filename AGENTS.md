# Работа в Celestial

Перед планированием и изменениями прочитай [цель](docs/project-goal.md), затем выбери руководства по задаче из [навигации документации](docs/README.md). Прочитай выбранные руководства до реализации; не загружай все документы и архив ADR автоматически. Для разработки читай стандарты кода и руководство компонента; для дизайна — design-workflow, руководства темы и релевантные design-reviews; для библиотеки — library-workflow; для обслуживания/передачи — maintenance.

Полные ADR и реестр читай при неоднозначности, исключениях, возможном конфликте, архитектурном изменении или аудите соответствия. Действующие ADR имеют приоритет над ошибочной документацией; заменённые — история. Порядок закреплён в ADR-0062 и описан в [рабочем процессе](docs/development-workflow.md).

## Обязательные ограничения

- При противоречии принятому решению до реализации назови ADR, требование, предлагаемую замену и последствия; дождись явного подтверждения конкретной замены. Уже полученное подтверждение повторно не спрашивай.
- references/ — приватные материалы. Не читай и не ищи там без явного поручения для конкретной задачи; исключай из общего поиска, Git, архивов и передачи. Не используй git add -f.
- В wordpress/ находится самостоятельный клиентский проект; приватная документация и library остаются снаружи. Тема без сборки, wp-env глобальный; инструменты сборки только в plugin/.
- Новые элементы сначала делай в wordpress/. Перенос в library — только по запросу. До изменения или удаления существующих библиотечных файлов покажи точный список и дождись подтверждения; переименование и перемещение также считаются изменением. Поручение на wordpress/ не распространяется на library/.
- Не выдавай принятое решение за реализацию или непроверенный результат за готовый. Документируй ограничения. «Обсудим позже» сохраняй в questions без запуска работы; содержательные отзывы — в design-reviews.
- После добавления ADR/изменения статуса обнови затронутую документацию и сохрани связанные изменения локальным Git-коммитом: явные пути, проверка индекса, без несвязанных/приватных файлов. Push — только по отдельному указанию.

Подробные технические требования находятся в тематических руководствах: не добавляй сюда новые пересказы каждого ADR. При изменении решений поддерживай руководства, ссылки и фактическое состояние; не меняй архитектурные решения молча ради совпадения с кодом.
